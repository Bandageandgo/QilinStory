# 高難度檢定新戲：多 agent 流程（第二級，作者 2026-09-26 定）

> **適用範圍：** `給AI看的指南/高難度檢定走向指南.md` 第十一節〈已定場次清單〉裡，作者已定好分類、檢定、掛點的場次。
> **規則本身**（分類、選項格式、題語、引擎寫法、固定旁白、`IsHiddenN`、探險事件、密度）**以走向指南為準**，本檔只管「誰做什麼、依什麼順序」。
> **執行工具：** `.claude/wf/hard-check-v2.js`，用 Workflow 工具跑。
> - 必填參數：`args.date`，填當天日期。
> - 選填參數：`args.only` 只跑某幾場；`args.have` 標出哪些場的情境包或起草稿已存在、可以沿用。
>
> ⚠ **跨機注意：** `.claude/` 整個資料夾未進 git（見本檔第八節）。到另一台電腦要先確認腳本在。

## 一、分工（一場戲七名 agent，加一名箱庭共用的整理）

| 步驟 | 人數 | 推理強度 | 產出 |
| :--- | :--- | :--- | :--- |
| 整理情境 | 一個箱庭一名 | xhigh | 情境包檔案 ＋ 一頁摘要 |
| 起草 | 每場三名，各寫一版 | xhigh | `draft-甲／乙／丙.md` |
| 審修 | 每場三名，一人負責一版 | **max** | `revised-甲／乙／丙.md` |
| 終審兼寫檔 | 每場一名 | **max** | 提案檔 `劇情/<箱庭>/高難度檢定_<場>.md` |

- **模型一律 Opus 5.5。** 腳本裡寫死 model，不靠繼承主對話的模型。
- **推理強度（作者 2026-09-27 定）：全部最低 xhigh；審修與終審是品質關卡，用 max。** 原因：文本品質不穩。第六節的實測數字是 medium／high 時量的，現在會更慢、更花。
- **所有場次同時跑，不分組排隊。** 同一箱庭的幾場戲等同一份情境包。
- **暫存檔放在 scratchpad 的 `hc/<箱庭或場>/` 底下，不進專案。**

## 二、各步驟做什麼

### 1. 整理情境

把後面的人需要的東西**逐字抄**成一份情境包 `hc/<箱庭>/packet.md`，**只抄事實、不提改法**。內容有：

1. 走向指南相關節的原文。
2. 每場掛點前十格到接回點後十格的原文。
3. JSON 的連線與 parent。
4. 每條會播到掛點的來路與條件，含有娜娜／沒娜娜。
5. 骰子亮的既有句。
6. 每個出場角色在本箱庭說過的每一句話。
7. 設定檔段落。
8. 未卜的兌現處候選。
9. **〈指南摘錄〉**：把三份必讀指南和各轉換規則裡寫這場戲用得到的節**逐字抄**進來。範圍包括：
   - 文本創作指南：第零層、0.2.3、0.6、2.1a。
   - 世界觀：第八節。
   - 武俠文風創作指南：旁白卡、主角卡、出場角色聲口卡、7.1a–7.1c、7.3、自檢清單。
   - 饕餮廢案清單（`@角色設定/饕餮.md` 第十節）。
   - 轉成json指南：§1 詞表、§4.2。
   - 擲骰指令轉換規則：四段寫法與 ID 對照表。
   - 立繪指令轉換規則：可用格號。

回傳給下游的只有一頁摘要，細節都在檔案裡。

### 2. 起草（三名，各一個取向）

- **轉機**的三個取向差在**演法**：照清單最省、最接這場戲原本嗓子、刻意換一種演法。
- **福禍**的三個取向差在**禍的種類**（作者 2026-09-27，猴群第一案退回後定）：甲＝禍落在對方怎麼看你；乙＝禍落在同伴或旁人身上；丙＝另一種出乎意料的後果。三版的禍都**不得**像同一選單一般檢定的失敗換個說法，不得推進那場戰鬥，不得嚇昏嚇跑丟下同伴。腳本逐場把一般失敗長什麼樣寫進情境包，起草者對照著避。
- **未卜**的三個取向差在**秘密本身**，由腳本逐場指定，例如藏寶、把柄、一條原本沒有的路。
- > ⚠ **作者准的例外（作者 2026-09-26 准，只限本流程的起草步驟）：起草者只讀情境包，視同讀過 `CLAUDE.md` 規定必讀的三份指南。** 因為情境包第 9 項已把用得到的節逐字抄進來。**其他步驟、其他工作照 `CLAUDE.md`。** 別的 agent 讀到 `CLAUDE.md` 的必讀規定時，以此條為准許的例外，兩邊不矛盾。
- 起草只管寫戲，**不回 JSON 查連線**，連線交給審修。只有情境包缺了非要不可的東西才回原檔讀那一段，並記一筆。
- 寫完只跑一次 `文風節奏檢查.py`，照報告修一次就交。
- 稿子的固定結構：**取向、秘密、檢定、掛點與接回、讀的條件、寫的指令、戲、兌現處、起草者自檢。**

### 3. 審修（一人一版）

- 逐項查本場**八項檢查**，回原 JSON 和總覽稿查證：連線、來路、既有格有沒有被改、留白、擲骰結構、獎勵與代價、選項格式、`Description` 詞表。
- 逐句查文風規矩，口吻對照情境包裡的既有句。
- 另外依分類加查：
  - **未卜**：拿到的東西是不是「額外」的。
  - **轉機**：是不是真的翻盤、接回勝利線之後有沒有動到。
  - **福禍**：禍有沒有越過紅線。
- 能修的直接修，**但要守住那一版的取向，不能修成別版**。不該由 AI 定的留空白，記進〈待作者定〉。
- 每一處改動記進〈審修紀錄〉：第幾格、原句、新句、依哪條規矩。
- 修完跑 `文風節奏檢查.py` 和 `高難度檢定檢查.py`。
- 選一個人審三版不會更省 token，而且比較慢，所以採一人一版。

### 4. 終審兼寫檔

- 讀完三版審修稿，再挑一次錯。重點放在審修最容易漏的地方：每條來路接不接得通、擲骰結構、獎勵指令、三版是不是三個真的不同的選擇。
- 標一版建議版，附一句理由。
- 寫提案檔：
  - 第一行寫 `# 〈場〉　高難度檢定提案（〈分類〉）｜創作稿／提案，尚未進 JSON`。
  - 引用區塊寫掛點與接回、建議版、待作者填。
  - 三版各一節，每節含戲、兌現處、審修紀錄。
  - 最後是合併去重的〈待作者定〉和〈審修摘要〉。
- 跑兩支檢查腳本，確認**只動了提案檔**，沒動 `Json/`、回讀稿、走向指南。

## 三、作者挑版之後：定稿

> **2026-09-27 起可用腳本跑這一步：** `.claude/wf/finalize-and-convert.js`（作者裁示寫進 `args.jobs`），每份提案檔一名定稿、一名轉 JSON、一名獨立複核，三步都是 max，同一份 JSON 的幾份依序寫。手動派單一 agent 的做法仍可用，但吃不到 max。

作者給出「選哪版、難度多少」後，每場一名 agent **只改那一份提案檔**。

- 在檔頭引用區塊之後新增 `## ✅ 定稿（作者〈日期〉選定：版〈X〉，〈檢定〉〈難度〉）`，放選定版改好的完整戲，之後轉 JSON 以這一節為準。
- 定稿時套用當下已定的規則。**這一批套用的是：**
  - 骰子亮一律是選單前最後一格，用固定句一字不改（走向指南七之二）。
  - 未卜的變數用作者給的 `IsHiddenN`。
  - 未卜的兌現改成探險事件，另寫一句情報網提示句（照 `劇情/探險事件提示.md`）。
  - 轉機的選單至少兩項：轉機選項＋「離開」（接回原失敗線）；轉機不過先 `ModifyData(Coin,-200)`、不寫解釋台詞，再接回原失敗線（作者 2026-09-26）。
  - 福禍過的專長經驗是該對話一般檢定的三倍；未卜、轉機過的跟一般檢定一樣（作者 2026-09-26）。
  - 福禍、未卜一定跟著同種的一般檢定並排；選單裡沒有同種一般檢定的，連一般難度那一項一起加（作者 2026-09-27；轉機除外）。
  - 未卜過了一定另給一個機會點 `ModifyData(ChancePoint,1)`，可以只給機會點（作者 2026-09-27）。
- 其他台詞不動。非改不可的，節末〈定稿改動〉逐條記原句、新句、理由。
- 原三版留在後面，節標題加「（選定前原稿）」或「（未選，留存）」。
- 〈待作者定〉改寫成只剩定稿版仍有效的事。
- 定稿節跑兩支檢查腳本**必須乾淨**。未選各版裡的舊句被報警告可以不管。
- 之後才是轉 JSON：續號、補 `zh_CN`、跑 `json順序檢查.py`、走 `Unity對話同步流程.md`、回讀、更新走向指南登記表。

## 四、檢查腳本

- `給AI看的指南/文風節奏檢查.py`：抓碎句、超長台詞、em7 與表情特效用量。
- `給AI看的指南/高難度檢定檢查.py`（2026-09-26 新寫），檢查以下各項：
  - 選項格式與三句題語，以及題語和分類對不對得上。
  - 檢定標籤是不是遊戲既有的。
  - 擲骰四段包裝、手動檢定、`FeatID`、難度格式。
  - `IsPassDice` 成敗兩邊齊不齊。
  - 變數、任務號、教學 ID 是既有的，或留 `＿＿`，或是作者定名的。作者定名的變數寫在腳本的 `AUTHOR_VARS`，目前只有 `IsHidden1`（新號要一併加進去）。
  - `SetFlag`、`title` 禁用。
  - `Description` 在不在詞表內。
  - em7 密度、`[/em7]` 後的標點。
  - 硬紅線詞；骰子格不寫燙熱顫震。
  - 骰子亮是不是固定句。
- ⚠ 腳本已知的小毛病：說明文字裡貼了擲骰指令原文，會被誤判成擲骰格，要改成白話描述。
- ⚠ 腳本尚未檢查的兩條（2026-09-26 新規，待補）：轉機選單有沒有「離開」；轉機不過那格有沒有 `ModifyData(Coin,-200)`。

## 五、跑的時候要注意

- **額度：** 五小時額度用完時，正在跑的 agent 全部失敗、回傳空值，不會自己重試。要看 transcript 資料夾裡的 `journal.jsonl` 有沒有 `failed`，額度恢復後再續跑。
- **續跑是前綴比對：** `resumeFromRunId` 照 agent 呼叫順序一條一條比，第一個不同的呼叫之後全部重跑。改腳本加新場次會打掉舊場次的快取。要保住成果，把已完成的情境包和起草稿存檔，用 `args.have` 沿用。
- **跑之前先鎖住規則：** 開跑後才改指南，會讓整批重做。
