# 多 Agent 創作流程（共同規則；作者 2026-09-28 定為所有創作內容通用；2026-09-29 晚改成第四級）

> **中心目標（作者 2026-09-29 定）：** 所有文字內容由作者審核；AI 的工作是**生出讓作者挑的東西**，不是替作者判斷好不好。作者審的方式一律是**三選一**：先挑大綱，再標出不過關的句子、對那些句子挑三選一。文字定了之後，指令、JSON、各種檢查才交給 agent。作者管的是句子的水準與人物口吻；AI 管的是機械活、規矩、事理。
> **為什麼這樣改：** 第三級（十五名 agent，十名在審）跑英布一場兩個半小時，作者最後還是要從頭讀三版。AI 審一遍、作者再審一遍是重複勞動；規則追不上作者的品味，審修改對了看不出、改錯了要退回。三選一把判斷還給作者，而且每一個判斷都直接進文本。
> **適用範圍：** 凡是要**生出或改寫遊戲文本**的活——高難度檢定新戲、蝴蝶效應分支、回音一句、人物線與事件的新劇本——都照本檔跑。各用途只差「讀哪份規則、大綱要定什麼、稿放哪、定稿另套用什麼」，列在第九節。審稿單改稿是既有稿逐條修，形狀另計（第九節末列）。
> **規則本身**（那場戲該怎麼寫）不在本檔：文風看三份必讀指南；高難度檢定看 `高難度檢定走向指南.md`；蝴蝶效應看 `劇情/蝴蝶效應_素材與設計.md` §一、§三、§八；回音看同檔 §九；人物線看該角色資料夾的設計端與 `@角色設定/`。本檔只管「誰做什麼、依什麼順序」。
> **執行方式：** 第四級的每一步之間都有作者做決定，所以**不用一支 Workflow 從頭跑到尾**，一步派一名 agent（Agent 工具或一支只跑那一步的小腳本），作者決定了再派下一步。只有最後「定稿→轉 JSON→複核」照舊用 `.claude/wf/finalize-and-convert.js`。配套腳本：`給AI看的指南/情境包產生器.py`（底稿與指南摘錄）、`提案檔組裝.py`（對話置頂版面，一版也能組）、`文風節奏檢查.py`（含 `專名表.txt`）、`高難度檢定檢查.py`、`json順序檢查.py`。舊母版 `hard-check-v3.js`、`luxin-yingbu-v3.js` 留作對照（第七節）。
>
> ⚠ **跨機注意：** `.claude/` 整個資料夾未進 git（見本檔第八節）。到另一台電腦要先確認腳本在。
> **沿革：** 本檔原名 `高難度檢定_多agent流程.md`（2026-09-26 第二級）；2026-09-28 作者定為共同規則、改名；2026-09-29 早上第三級（串行起草、差異判定、文風審、邏輯審）；2026-09-29 晚上作者定為第四級（本版）。第一到第三級的形狀與實測都在第六、七節。

## 一、分工（第四級：一場戲六到八名 agent，沒有審的 agent）

| 步驟 | 誰 | 推理強度 | 產出 | 作者在這裡做什麼 |
| :--- | :--- | :--- | :--- | :--- |
| 0. 底稿 | 腳本，沒有 agent（派下一步的人順手跑） | — | `packet-base.md`（名單表、掛點前後、來路、既有句、退稿實例）＋ `指南摘錄.md` | — |
| 1. 大綱三選一 | 一名 | xhigh | `<場>_大綱三選一.md`：三份大綱，串行寫、差在結構與演法 | **挑一份**，可直接改字 |
| 2. 全稿一版 | 一名 | xhigh | `<場>.md`：照作者挑的大綱從頭寫到尾，**指令一起寫**（立繪、表情、擲骰、戰鬥、背景、轉場、Description；ID、數字、音樂情境留 `＿＿`）；對話置頂；交稿前腳本零警告 | **讀一遍，標出不過關的句子**（可寫一句方向；可框一段整段重寫） |
| 3. 標句三選一 | 一名（一輪一名，通常兩三輪） | xhigh | 每個標記三個候選，寫回同一份稿的〈三選一〉表；**作者點完由 `三選一套入.py` 套進對話與逐格（2026-09-30 起不派 agent 套）** | **每列挑一個**（主對話開成系統選單一題一列，一輪四題；不叫作者回 md 讀表，作者 2026-09-30 定）；都不要就寫方向再來一輪 |
| 4. 邏輯審 | 一名，**全稿一出來就派，跟作者標句同時跑**（排班，作者 2026-09-30 定） | xhigh（作者 2026-09-30：這一步只列六件事，xhigh 夠） | 只列不改：誰知道什麼、先後、東西去向、旁白台詞不打架、分支前提、前後場接口；確定的問題併進**第一輪**三選一表 | 跟其他列一起挑 |
| 5. 填 `＿＿`、轉 JSON、簡體、複核 | **腳本三支＋翻譯一名**（2026-09-30 起不派定稿人、不派複核）；**翻譯在文字一定就派，跟作者填 `＿＿` 同時跑** | 翻譯 high | 主對話把稿裡的 `＿＿` 連上下文開成系統選單問作者 → `逐格轉json.py` 轉檔 → `填簡體.py --出表` → 翻譯 agent 填表 → `填簡體.py --填` → `json複核.py`（稿與 JSON 逐格比對、順序、簡體、留白、禁詞） | 用選單填 `＿＿`（ID、難度、好感數字、任務號、音樂情境）；複核乾淨後走 Unity 同步 |

- **沒有審修、文風審、終審。** 規矩、格式、留白、縮寫、節奏交腳本，交稿前自己跑到零警告；句子好不好交作者。
- **模型（2026-09-30）：** 在 Cursor 跑第四級，一律 Grok 4.7、推理 high。大綱、全稿、標句三選一、邏輯審、翻譯都同一檔。這個聊天先在模型選單設成 Grok 4.7 High，子代理用繼承，不另填 `grok-4.7-high-fast`。另一台若用 Claude Code，仍是 Opus 5.5，推理照上一表（多為 xhigh，翻譯 high）。派的時候寫明。
- **每一步只動自己該動的檔**：大綱檔、該場的 .md；`Json/`、回讀稿、角色檔、指南一律不動，到第 5 步才碰 JSON。
- **派出去的 agent 一律寫明 git 只准讀。** 2026-09-27 有一名 agent 用 `git stash` 還原時把 71 個 LF 檔寫成 CRLF，收拾了一整批。
- **暫存檔放在 scratchpad 的 `hc/<場>/`；指南摘錄放 `hc/common/指南摘錄.md`，所有場共用。** 大綱檔與全稿放專案裡該場的位置（第九節），因為作者要在上面挑。
- **在 Cursor 跑要知道的四件事（2026-09-30）：** ①Cursor 沒有 scratchpad，暫存放 `.cursor/tmp/hc/<場>/`（跟 `.claude/` 一樣不進 git）；②Cursor 沒有系統選單，作者挑三選一改成**直接填表的「作者選」欄**（`三選一套入.py` 讀的就是那欄）或在聊天裡回「C 丙、D 甲…」由 agent 填進表；填 `＿＿` 同理；③Cursor 沒有 Claude Code 的 hook，改檔不會自動跑節奏檢查，所以每一步「交稿前腳本零警告」要 agent 自己跑；④`CLAUDE.md` 不會自動載入，硬紅線靠 `.cursor/rules/qilin-story.mdc`（已補齊四條：變數與任務號留 `＿＿`、`SetFlag` 禁用、`title` 不動、`Description` 只准詞表）。流程、腳本、檔案格式跟 Claude Code 完全一樣，換模型只換第一節這一條；第一場跑完把真數補進第六節，跟把脈那組比。

## 二、各步驟做什麼

### 0. 底稿（腳本）

```
python -X utf8 給AI看的指南/情境包產生器.py --json "<JSON>" --anchors <掛點格號> --overview "<回讀稿>" --speakers <會開口的每個 actorID> [--extra-json <參考 JSON>] --out hc/<場>/packet-base.md
python -X utf8 給AI看的指南/情境包產生器.py --摘錄 [--高難度] --out hc/common/指南摘錄.md
```

底稿給：①**出場名單表**（角色｜ID｜本檔句數｜角色檔有無｜聲口卡有無｜全案既有台詞句數；沒卡沒檔的標 ⚠）；②掛點前後十格逐字；③來路；④既有擲骰／戰鬥／教學格；⑤變數與任務；⑥每個角色的聲口卡全文、角色檔前段、既有台詞、**退稿實例**（從全案「✏ 改稿：原句→新句」註記裡抓這個角色的）。新劇本沒有掛點就不給 `--anchors`，拿同線的 JSON 跑，要的是名單表、聲口卡、既有句、退稿實例。指南摘錄一次做好，指南改了才重做。

**規矩：只准名單表上的人開口。** 沒聲口卡的照〈路人與配角通則〉，並在稿尾記一筆。

### 1. 大綱三選一（一名，xhigh）

- 讀：這個用途的規則（第九節）、設計端或已定場次那一列、底稿、指南摘錄最前面的〈常犯十條〉。
- **串行寫三份**：甲先寫；乙必須跟甲不同；丙必須跟甲乙都不同。不同看四樣：拍子、結果、誰先開口、關鍵動作或物件；四樣裡兩樣以上相同就算太近，自己重寫。乙、丙附〈差異表〉。
- **大綱寫到哪裡為止：** 拍、誰在場、誰先開口、講什麼事、關鍵動作或物件、結果落哪、接回哪一格；分岔一條一條列；轉場與背景換幾次。**不寫句子**，不寫台詞。節奏在這裡定：每一拍幾格上下、旁白與台詞的比例。
- 寫成 `<場>_大綱三選一.md`（位置見第九節）：

```
# 〈場〉　大綱三選一（〈用途〉）｜〈日期〉
> 作者挑一份，可以直接在上面改字；挑定後寫「✅ 作者選 甲／乙／丙（日期）」在這一行底下。
## 大綱甲（一句取向）
| 拍 | 誰在場 | 誰先開口 | 講什麼事／關鍵動作 | 結果落哪 | 接回 | 格數上下 |
…
分岔：…
## 大綱乙（一句取向）
…（末尾〈差異表〉：對甲換了什麼）
## 大綱丙（一句取向）
…（末尾〈差異表〉：對甲、乙換了什麼）
## 待作者定
- 問題｜建議｜替代
```

- 回傳：三份大綱各一句、差在哪、待作者定幾條。**作者挑了才派下一步。**

### 2. 全稿一版（一名，xhigh）

- 讀：作者挑定（可能改過）的那一份大綱、底稿（名單表、每個角色的既有句與退稿實例）、指南摘錄。**先讀〈常犯十條〉錯例對改例，再讀本場角色的〈退稿實例〉，然後動筆。**
- > ⚠ **作者准的例外（2026-09-26 准，只限起草）：起草者只讀底稿與指南摘錄，視同讀過 `CLAUDE.md` 規定必讀的三份指南。** 其他步驟、其他工作照 `CLAUDE.md`。
- **一個人從頭寫到尾**，嗓子才一致。大綱定的拍、結果、誰先開口、接回，一個都不准改；覺得大綱有問題寫進〈待作者定〉，照大綱寫。
- 只准名單表上的人開口；主角標籤一律「你」；不寫內心話；硬紅線與禁詞照 `CLAUDE.md`。
- 每格底下寫逐格附註（actorID／Sequence／Conditions／Script／Description，有才寫；新格用【A】【B】…標；分岔 ▶；合流「→ 接 #N」；發言格接成敗兩支、選單格接各選項用 `- links: 【F】、【G】` 明寫；結尾 `- links: 空`）。**指令這一步就寫齊**（作者 2026-09-30 定，定稿人取消）：立繪與表情照 `立繪指令轉換規則.md`、擲骰四段、戰鬥、背景與轉場照 `畫面指令轉換規則.md`、Description 照詞表；**作者才能定的留 `＿＿`**：檢定難度、好感與錢的數字、任務號、變數名、教學 ID、音樂（`AudioControl(PlayMusic,＿＿)`，情境欄作者填）。
- **交稿前腳本零警告**：`文風節奏檢查.py`（碎句、超長、縮寫對專名表、結尾旁白短促、破折號、em7）；用途有格式檢查腳本的一併跑。報的自己修到不報，修不了的在〈待作者定〉說明。
- 版面用組裝腳本出（一版也能組）：

```
python -X utf8 給AI看的指南/提案檔組裝.py --場 <場> --用途 <用途> --分類 <分類> --日期 <日期> --建議 甲 --理由 "作者選定大綱〈X〉" --版 甲=<逐格稿> --out <場>.md
```

  組出來是：第一行 `# 〈場〉　〈用途〉｜創作稿／提案，尚未進 JSON`、引用區塊（大綱哪一份、掛點與接回、待作者填）、**`## 對話`置頂**（純對話，作者只讀這一段）、`## 待作者定`、`## 逐格（給 AI）`。組完在 `## 對話` 之後**加一節空的 `## 標記與三選一`**，給作者標。
- 回傳：稿的路徑、格數、腳本結果一句、〈待作者定〉幾條。

### 3. 標句三選一（一輪一名，xhigh）

**作者怎麼標（過渡做法，標句頁做好前）：** 讀 `## 對話` 段，把批註直接寫在那一格底下一行（作者 2026-09-29 張寧把脈第一輪就是這樣標的），或寫在 `## 標記與三選一` 底下一行一個：
```
- 【A12】 不像賈詡，太文
- 【A20】–【A26】 整段重寫：太拖，三格收掉
- 【B3】
```
方向可以不寫。也可以直接在對話裡把那句改掉（作者親改的句子 agent 不准再動）。標句頁（照審稿單頁那種、一格一列、點一下存雲端）做好後改用頁，規則不變。

**作者怎麼選（作者 2026-09-30 定）：一律用系統選單，不叫作者回 md 讀表。** agent 把候選表寫進 md 是留底；**主對話把每一列開成一題系統選項**（AskUserQuestion）：題目寫「【格】作者方向：原句」，三個選項各是甲／乙／丙的全文（括號裡註貼的是哪句既有句、換了什麼），一輪四題，選完再開下一輪；作者要都不要就用「Other」寫方向。選完由主對話把答案填進表的「作者選」欄，再派 agent 套進對話與逐格。大綱三選一也照這樣：三份大綱各寫成一句取向＋一段拍子摘要當選項；作者的追加方向（例如張寧把脈加露角、改拍子順序）寫進大綱檔檔頭「✅ 作者選」那段當規格。**理由：** md 裡的三欄表很難讀；選單一次一題、答案直接進文本。

- agent 讀標記、該格前後五格、底稿裡那個角色的既有句與退稿實例。
- 檢查腳本**只跑、不讀原始碼**（作者 2026-09-30）：腳本印的報告就是它要的全部，讀程式碼只會多花兩分鐘、多堆兩萬 token 的上下文，對句子的精準度沒有幫助。其他要讀的照舊讀。
- **每一個標記給三個候選，寫進同一節的表：**

```
| 標記 | 原句 | 甲 | 乙 | 丙 | 作者選 |
| 【A12】 | … | …（貼既有句） | …（更省） | …（換動作或換說法） | |
```
  - 三個要真的不同：甲貼那個角色的既有句與退稿實例；乙更省字；丙換一個看得見的動作或換一種說法。不准三個都是換個形容詞。
  - **只准動那一句**（整段重寫的標記則只動那一段）：事實、前後格、指令、分岔一律不動；候選都要過腳本（可見字數、碎句、縮寫、破折號）。
  - 「作者選」欄留空給作者填甲／乙／丙，或「都不要：〈方向〉」。
- 作者填完，**跑 `python -X utf8 給AI看的指南/三選一套入.py <稿>`**（2026-09-30 起，套入不派 agent；把脈那次派 agent 套花了 17 分，腳本幾秒）：它讀表裡「作者選」那欄，把選中的候選換進 `## 對話` 與 `#### 戲` 底下那一格（保留說話者、`[panel=N]`、◆），整段候選少掉的格視同刪，在 `## 改動紀錄` 逐條記（格、原句→新句、作者選），表列標 ✅ 已套，最後跑一次節奏檢查。**刪掉的格它會把原本的 Sequence 印在提醒裡**，表情、立繪要不要併進鄰格，定稿人（第 5 步）決定。「都不要」的列它不動，再給三個候選成下一輪。
- 一輪的候選以標記數計，通常一名 agent 十分鐘內。**兩三輪收斂**；作者說「文字定了」才進第 4 步。

### 4. 邏輯審（一名，xhigh；作者 2026-09-30 從 max 降下來，只列不改；**跟作者標句同時跑**）

> **為什麼要有這一步：** 檀石槐線〈老兵的委託〉裡，主角前一句已經喊了「老丈」，旁白後一句才「認出」他，等於認了兩次；這種毛病作者看句子時不一定看，腳本也抓不到。

## 五、跑的時候要注意

- **額度：** 五小時額度用完時，正在跑的 agent 全部失敗、回傳空值，不會自己重試。Workflow 的要看 transcript 資料夾裡的 `journal.jsonl` 有沒有 `failed`，額度恢復後再續跑。
- **續跑是前綴比對：** `resumeFromRunId` 照 agent 呼叫順序一條一條比，第一個不同的呼叫之後全部重跑。
- **跑之前先鎖住規則：** 開跑後才改指南，會讓整批重做。
- **第四級每一步都短**，一步一名 agent 十到三十分鐘；長的是作者在中間做決定的時間，這是設計。
- **排班（作者 2026-09-30 定，三條都做）：** ①邏輯審不等作者標完，全稿一交就派，跟標句同時跑；②翻譯不等作者填 `＿＿`，文字一定就派；③作者在標這一場句子的時候，下一場的大綱先生出來。本地或雲端都不會讓模型變快，剩下能省的只有這種不讓人和 AI 輪流乾等的排法。
