# 戰鬥指令轉換規則

本文件說明如何在劇情 Markdown／JSON 中插入戰鬥。引擎層要求與擲骰相同：**必須用 `SetContinueMode` 包住，並等到結束訊息才放行**，否則打完畫面會卡住。勝負用 `IsPassFight()` 分流，與擲骰的 `IsPassDice()` 同一套欄位分工。轉 JSON 的節點結構見 `劇情/轉成json指南.md` §4.3。

## 一場戰鬥＝四個對話節點（必守）

| 順序 | 節點 | Sequence / Conditions |
| :--- | :--- | :--- |
| 1 | 戰鬥觸發（空對話） | **完整四段包裝**（見下） |
| 2 | 緩衝（空對話） | 只有 `Continue();` |
| 3 | 勝利分支 | `Conditions`: `IsPassFight() == true` |
| 4 | 失敗分支 | `Conditions`: `IsPassFight() == false` |

`IsPassFight()` **必須**寫在勝利／失敗節點的 **`Conditions`**（Markdown 寫 `**Condition IsPassFight() == true;**`），**禁止**寫進 `Sequence`。

## 第 1 句：完整包裝（必守）

⚠️ **禁止**只寫 `BeginFight(Combat,ID);` 或舊指令 `BeginCombat(...)`。

戰鬥觸發節點（空對話；Markdown 的 `**Sequence ...**` 同樣適用）必須**依此順序**寫滿四段：

```
SetContinueMode(false);
BeginFight(Combat,75);
SetContinueMode(true)@Message(EndFight);
Continue()@Message(EndFight);
```

寫成一行即：

```
SetContinueMode(false);BeginFight(Combat,75);SetContinueMode(true)@Message(EndFight);Continue()@Message(EndFight);
```

-   `Combat`：戰鬥類型（`FightingType`），目前劇本一律用 `Combat`。
-   `75`：戰鬥場次 ID（數字）。**依該場實際場次替換**，不可沿用範例數字。
-   訊息名稱是 **`EndFight`**，不是 `EndRoll`。
-   `BeginFight` **不得**跟 `SetPortrait`／`EnableCharacterExpression` 寫在同一條 Sequence。立繪、表情先寫在上一句對話。

### 與擲骰包裝的差異（不要抄錯順序）

| | 擲骰 | 戰鬥 |
| :--- | :--- | :--- |
| 核心指令 | `BeginDiceRoll(...)` 放在**最後** | `BeginFight(...)` 放在 **`SetContinueMode(false)` 之後、等訊息之前** |
| 結束訊息 | `EndRoll` | `EndFight` |
| 勝負條件 | `IsPassDice()` | `IsPassFight()` |

## 第 2 句：必須單獨 `Continue();`

戰鬥觸發節點的**下一個節點**必須是空緩衝，`Sequence` **只有** `Continue();`（不要把勝利旁白寫在這句上）。此節點的 `links` 指向勝利、失敗兩個分支。

## 第 3、4 句：條件分支

-   Markdown：`**(戰鬥勝利)**` 後接 `**Condition IsPassFight() == true;**`，再寫勝利劇情。
-   Markdown：`**(戰鬥失敗)**` 後接 `**Condition IsPassFight() == false;**`，再寫失敗劇情。
-   勝利／失敗旁白的 Sequence **不必**再寫 `Continue();`（已在第 2 句處理）。

### Markdown 範例（單場）

```
**Sequence SetContinueMode(false);BeginFight(Combat,77);SetContinueMode(true)@Message(EndFight);Continue()@Message(EndFight);**
**Sequence Continue();**
**(戰鬥勝利)**
**Condition IsPassFight() == true;**
**旁白:**：[panel=6]＊（……勝利描述……）＊
**(戰鬥失敗)**
**Condition IsPassFight() == false;**
**旁白:**：[panel=6]＊（……失敗描述……）＊
```

### JSON 範例（單場）

```json

    "actorID": "MC0",
    "text": "",
    "Sequence": "SetContinueMode(false);BeginFight(Combat,77);SetContinueMode(true)@Message(EndFight);Continue()@Message(EndFight);",

```

## 連續兩場（洞口兩邊一起上）

沒有合成場次。每一場都是完整的「四個對話」；第一場勝利才開第二場。第二場的完整包裝**不要**再加開頭的 `Continue();`（第一場的緩衝句已經 `Continue();` 過了）。

```
**Sequence SetContinueMode(false);BeginFight(Combat,76);SetContinueMode(true)@Message(EndFight);Continue()@Message(EndFight);**
**Sequence Continue();**
**(戰鬥勝利)**
**Condition IsPassFight() == true;**
**Sequence SetContinueMode(false);BeginFight(Combat,64);SetContinueMode(true)@Message(EndFight);Continue()@Message(EndFight);**
**Sequence Continue();**
**(戰鬥勝利)**
**Condition IsPassFight() == true;**
**旁白:**：……（兩場都贏）
**(戰鬥失敗)**
**Condition IsPassFight() == false;**
**旁白:**：……（第一場或第二場戰敗皆可走此段）
```

JSON：`76` 的緩衝 `links` 指向「開 64 的勝利節點」與「失敗節點」；`64` 的緩衝 `links` 指向「兩場都贏的旁白」與同一個（或各自的）失敗節點。

## 已廢棄寫法

| 錯誤 | 原因 |
| :--- | :--- |
| `BeginCombat(...)` | 舊名，引擎不走 `EndFight` 包裝 |
| `BeginFight(Combat,雍仔)` 等非數字 ID | 場次必須是數字 |
| 只寫 `BeginFight(Combat,77);` | 缺 `SetContinueMode`／`EndFight`，打完會卡死 |
| 與立繪寫在同一條 Sequence | 戰鬥必須獨立空節點 |
| 把 `IsPassFight()` 寫進 Sequence | 必須寫在 `Conditions` |
| 勝利／失敗旁白自己帶 `Continue();`、省略緩衝句 | 第 2 句必須是獨立的 `Continue();`，緩衝的 `links` 才分叉 |
| 省略失敗分支 | 一場戰鬥必須有勝、敗兩個條件節點 |

## 水濂洞場次 ID（《劇情/水濂洞的眼淚.md》）

| 戰鬥 | 場次 ID |
| :--- | :--- |
| 冰炎巨蛇／藍焰巨蛇 | `77` |
| 黑狼氏族 | `76` |
| 太平道 | `64` |

洞口威嚇失敗或全殺（兩邊一起上）：先 `76` 再 `64`，各走一輪四節點。其他劇本的場次以該場實際 ID 為準，不要套用本表。
