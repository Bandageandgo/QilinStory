# 擲骰指令轉換規則

> **⚠ 2026-08-27 更正兩處**（作者拍板，依 `Json/` 實際用法）：①四段包裝的第二段是 **`SetContinueMode(original)`，不是 `SetContinueMode(true)`**——`original` 是「還原成進來之前那個模式」，`true` 會把玩家原本的手動模式強制改成自動推進。全案統計 `original` 401 處、`true` 僅 6 處（且那 6 處是照本檔舊版寫的），`古墓演出劇情.json` 的過場、戰鬥、技能卡、粒子格也一律 `original`。②擲骰格的 `actorID` 是 **`"0"`，不是 `"MC0"`**——`MC0` 這個 ID 在整個 `Json/` 與 `立繪指令轉換規則.md` 角色表裡都不存在。

本文件旨在說明如何在劇情文本中，根據擲骰事件的類型與結果，正確地插入指令以給予玩家獎勵。

## 擲骰類型

遊戲中的擲骰主要分為以下兩種：

1.  **系統擲骰 (自動檢定)**:
    *   此類擲骰由系統自動觸發並完成檢定。
    *   檢定結果（成功/失敗）會直接通過「即時訊息區」告知玩家。
    *   **指令範例（Sequence 必須完整包裝；指令名是 `BeginDiceRoll`，禁止寫 `DiceRoll`）**:
        ```
        SetContinueMode(false);
        SetContinueMode(original)@Message(EndRoll);
        Continue()@Message(EndRoll);
        BeginDiceRoll(Auto,InsightCheck,12);
        ```
        寫成一行即：`SetContinueMode(false);SetContinueMode(original)@Message(EndRoll);Continue()@Message(EndRoll);BeginDiceRoll(Auto,InsightCheck,12);`
        （`FeatID`／難度依情境替換。完整規則見「擲骰節點的 Sequence 固定寫法」。）

2.  **手動擲骰 (選項回應)**:
    *   此類擲骰通常與玩家的對話選項相關聯。
    *   玩家選擇帶有檢定需求的選項後，系統進行檢定。
    *   檢定結果會導向不同的對話分支或劇情發展（成功分支/失敗分支）。
    *   **重要**: 玩家點選帶檢定的選項後，**緊隨該選項節點之後**必須插入一個「空對話」擲骰節點（`text` 為 `""`，`actorID` 為 `0`）。此節點的 `Sequence` **不能只寫** `BeginDiceRoll(...)`，必須使用下方固定四段包裝。
    *   **指令範例**:
        1.  **空對話擲骰節點**: 放在帶檢定的選項節點**之後**。例如魅力檢定難度 6：
            ```json
            {
                "entryID": 100, // 節點ID (範例)
                "actorID": "0", // 系統節點，無實際發言者（⚠ 舊版寫 `MC0`，那個 ID 不存在；全 `Json/` 的擲骰格一律寫 "0"）
                "text": "",       // 無對話內容 (空字串)
                "Sequence": "SetContinueMode(false);SetContinueMode(original)@Message(EndRoll);Continue()@Message(EndRoll);BeginDiceRoll(Manual,CharismaCheck,6);",
                "links": [101]  // 只連一個緩衝節點；該節點若無對話才在 Sequence 開頭加 Continue();
            }
            ```
        2.  **對話選項標註**: 接著，在玩家的對話選項中正常標註檢定信息，例如：`1.  [魅力 難度6]：「三百文？小意思！」`。遊戲系統會將此選項與先前 `BeginDiceRoll` 指令的結果相關聯。

## 擲骰節點的 Sequence 固定寫法（必守，否則流程卡死）

⚠️ 這是引擎層的硬性要求，手動（`Manual`）與自動（`Auto`）擲骰皆適用：

1.  **擲骰觸發節點**（空對話節點；Markdown 的 `**Sequence ...**` 同樣適用）的 `Sequence` **不能只寫** `BeginDiceRoll(...);`。    必須**依此順序**寫滿四段。指令名是 **`BeginDiceRoll`**，**沒有** `DiceRoll(...)` 這個指令。先暫停對話、等收到擲骰結束訊息（`EndRoll`）才放行：

    ```
    SetContinueMode(false);
    SetContinueMode(original)@Message(EndRoll);
    Continue()@Message(EndRoll);
    BeginDiceRoll(Auto,InsightCheck,12);
    ```

    手動檢定把最後一段的 `Auto` 改成 `Manual`、檢定 ID 與難度依情境替換即可，例如：
    `SetContinueMode(false);SetContinueMode(original)@Message(EndRoll);Continue()@Message(EndRoll);BeginDiceRoll(Manual,PoliticsCheck,12);`

    （Markdown 劇本裡的 Sequence 也必須寫完整包裝，不能等到轉 JSON 才補。）

2.  **擲骰觸發節點之後固定隔一個節點才分支**：擲骰節點的 `links` **只能指向一個**「緩衝節點」；`IsPassDice()` 的成功／失敗 `Conditions` 一律寫在**再下一層**的分支節點上，**禁止**把 `Conditions` 直接掛在緊接擲骰節點的那個節點。

3.  **緩衝節點要不要 `Continue();`，看它有沒有對話內容**：

    | 緩衝節點狀況 | `Continue();` | 原因 |
    | :--- | :--- | :--- |
    | `text` 為 `""`（沒有對話） | **必須**寫在 `Sequence` 最前面 | 沒有台詞可讓玩家點擊推進，少了 `Continue();` 擲骰結束後畫面會停住 |
    | `text` 有台詞（例如主角執行選項的發言） | **不要寫** | 這句台詞本身就會等玩家點擊推進；多加 `Continue();` 只是把 `Sequence` 拉長，還可能把這句台詞直接跳過去 |

    無對話的緩衝節點（自動檢定、或選項後主角不發言時）：

    ```json
    {
        "entryID": 100,
        "actorID": "0",
        "text": "",
        "Sequence": "Continue();",
        "links": [101, 102]
    }
    ```

    有對話的緩衝節點（手動檢定後主角把選項那句話說出來）：

    ```json
    {
        "entryID": 100,
        "actorID": "MC1",
        "text": "「老闆，你看這事能不能……」",
        "Sequence": "SetPortrait(MC1,pic=5);EnableCharacterExpression(0,MC1-1,Proud);",
        "links": [101, 102]
    }
    ```

### 常見錯誤（擲骰）

| 錯誤寫法 | 為什麼錯 |
| :--- | :--- |
| `DiceRoll(Auto,InsightCheck,12);` | **沒有這個指令**。必須寫 `BeginDiceRoll`，且要四段包裝 |
| `Sequence` 只寫 `BeginDiceRoll(Auto,InsightCheck,12);` 或 `BeginDiceRoll(Manual,XXCheck,10);` | 缺 `SetContinueMode`／`EndRoll` 包裝，擲完會卡死 |
| 擲骰格再摻 `SetPortrait`／`EnableCharacterExpression`／`ModifyData`／`SetFlag` | 擲骰格只放那四段、`text` 必須為 `""`；立繪表情放到下一格 |
| 擲骰格的 `text` 寫台詞 | 擲骰格是純指令節點，台詞要放到下一格 |
| 有台詞的那格還寫 `Continue();SetPortrait(...)` | 台詞本身會等玩家點擊，多的 `Continue();` 只是拉長指令，還可能跳過這句 |
| 空對話緩衝格漏了 `Continue();` | 沒有台詞可推進，擲骰結束後畫面停住 |
| 把 `Conditions: IsPassDice() == true` 直接掛在擲骰格的下一格 | 必須先隔一格緩衝，成功／失敗分支在再下一層 |
| `IsPassDice()` 寫進 `Sequence` | 成敗判斷只能寫在 `Conditions` 欄位 |
| 拆出「大成功」第三條分支 | 只有成功／失敗兩級 |

## 檢定成功獎勵規則

無論是系統擲骰還是手動擲骰，只要檢定成功，都應在「即時訊息區」給予玩家相應的經驗值獎勵。

*   **通用獎勵標準**: 檢定成功，對應的「五維屬性」或「專長」經驗值 **+10**。
*   **口才檢定特例**: 檢定成功，口才專長經驗值 **+25**，指令為 `ModifyData(FeatExp,Player,Persuasion,25);`。
*   **結果分級**: 檢定僅分 **成功**／**失敗**，**沒有「大成功」** 第三級；轉 JSON 時成功／失敗各一條分支即可。
*   **已廢棄指令**: 勿使用 `ModifyData(RangerFame,...)` 作為檢定獎勵。

*   **指令格式**:
    *   **五維經驗值**: `ModifyData(AbilityExp,Player,AbilityID,10);`
        *   `Player`: 代表玩家（或主角）。
        *   `AbilityID`: 對應的五維屬性ID，**必須用完整英文名稱**（與 `對話系統指令.csv` 一致），**禁止**寫成 `Ability_INT`、`Ability_POL` 這類縮寫：
            | 五維 | AbilityID |
            | :--- | :--- |
            | 統率 | `Leadership` |
            | 武力 | `Strength` |
            | 智力 | `Intelligence` |
            | 政治 | `Politics` |
            | 魅力 | `Charisma` |
        *   **注意**: `StrengthCheck`, `CharismaCheck` 等是檢定本身的標籤ID。獎勵五維經驗時，應使用上表的 AbilityID。例如魅力檢定成功應寫 `ModifyData(AbilityExp,Player,Charisma,10);`，智力檢定成功應寫 `ModifyData(AbilityExp,Player,Intelligence,50);`。
    *   **專長經驗值**: `ModifyData(FeatExp,Player,FeatID,10);`
        *   `Player`: 代表玩家（或主角）。
        *   `FeatID`: 對應的專長ID，參考 `異麒麟所有ID命名.xlsx - 特殊標籤(職骰).csv` (例如：醫術檢定 `MedicalExpertiseCheck` 對應的專長ID為 `MedicalExpertise`，經濟檢定 `EconomicDevelopmentCheck` 對應的專長ID為 `EconomicDevelopment`)。
        *   **注意**: 同樣地，獎勵專長經驗時，應使用專長本身的ID。

## 成功／失敗分支條件（`Conditions` 欄位）

*   `IsPassDice() == true` / `IsPassDice() == false` 必須寫在分支節點的 **`Conditions`** 欄位，**禁止**寫進 `Sequence`。
*   成功分支第一個節點：`"Conditions": "IsPassDice() == true"`
*   失敗分支第一個節點：`"Conditions": "IsPassDice() == false"`
*   角色發言節點（擲骰後共用台詞）的 `links` 指向 **2 個** `entryID`（成功、失敗），不是 3 個。

## 範例

**情境1: 系統自動洞悉檢定成功**

```
// 前一個可能是旁白節點，描述了觸發檢定的情境，其 links 指向 entryID: 99
// 例如：
// {
//     "entryID": 98,
//     "actorID": "0",
//     "text": "[自動洞悉檢定] (難度 2) 你試圖觀察老伯的反應。", 
//     "Sequence": "",
//     "Description": "描述自動洞悉檢定的觸發情境與文字提示",
//     "links": [99]
// },

// 檢定觸發節點 (此節點不應包含遊戲內可見的文字)
{
    "entryID": 99, 
    "actorID": "0",
    "text": "", // 文字為空
    "Sequence": "SetContinueMode(false);SetContinueMode(original)@Message(EndRoll);Continue()@Message(EndRoll);BeginDiceRoll(Auto,InsightCheck,2);",
    "Description": "自動洞悉檢定觸發點 (難度2)",
    "links": [100] // 指向空內容緩衝節點
},
// 空內容緩衝節點 (此節點用於隔離指令與後續分支，Sequence 開頭必須有 Continue();)
{
    "entryID": 100,
    "actorID": "0",
    "text": "",
    "Sequence": "Continue();",
    "Description": "自動檢定後的空緩衝節點",
    "links": [101, 102] // 假設101是成功分支，102是失敗分支
},

// 成功分支的旁白
{
    "entryID": 101,
    "actorID": "0",
    "text": "[PANEL=6]＊（你注意到老伯在說出價格時，眼神似乎閃爍了一下，嘴角有著一絲不易察覺的弧度，似乎這價格並非表面那般簡單。）＊",
    "Sequence": "ModifyData(FeatExp,Player,Insight,10);DisableCharacterExpression(0);", // 獎勵指令在此
    "Description": "洞悉檢定成功後的旁白與獎勵",
    "links": [103] // 指向玩家選擇回應的教學提示 (或直接指向選項)
}
// ... 後續節點 ...
```

    "text": "「我想用魅力說服他！」", // 選項的純文字
    "Sequence": "",
    "links": [103] // 指向緊隨的空擲骰節點

## 相關文件

戰鬥同樣需要 `SetContinueMode` 包裝，但**順序與訊息名稱不同**（`BeginFight` 不放最後；等的是 `EndFight` 不是 `EndRoll`）。勝負條件為 `IsPassFight()`（對應擲骰的 `IsPassDice()`），一場戰鬥固定四個對話節點。見同資料夾 `戰鬥指令轉換規則.md`。
