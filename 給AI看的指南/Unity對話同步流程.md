# Unity 對話同步流程（Json ⇄ DialogueDatabase）

> 本檔規範 AI（Cursor / Claude Code）如何把文案變更送進 Unity，以及新對話、翻譯怎麼走同一條管線。
> Unity 端工具：`DialogueJsonBridge.cs`（選單 **Tools → 對話輔助工具 → JSON 匯入匯出（文案同步）**）。

## 第零條：`Json/` 是遊戲內文案的唯一事實來源

```
劇情/*.md（創作區） ──AI依轉成json指南轉換──▶ Json/*.json ◀── AI 修正 / 翻譯（作者在 IDE 核准 diff）
                                                  │   ▲
                                             匯入 │   │ 匯出（把 Unity 現況倒回來）
                                                  ▼   │
                                         Unity DialogueDatabase
```

- 要改遊戲裡的對話，**改的是 `Json/` 裡的 JSON**，再用 Unity 端工具同步進資料庫。
- **不要**直接在 Unity 的 Dialogue Editor 改文字。不得已改了，必須先「匯出」回寫 JSON，讓兩邊重新一致。
- AI 的所有修改都以 IDE 的 diff 呈現，**作者按「接受」才算數**；Unity 匯入時還有第二道摘要確認。

## 鐵則（違反會讓對應關係永久損壞）

1. **`entryID` 是永久錨點**：節點一旦同步進 Unity，它的 `entryID` 就不可再改。
   - 改文字＝只改欄位值，**不改號**。
   - 刪節點＝整個物件移除，**不把後面的號碼往前補**。
   - 新節點＝用 **全檔最大 entryID + 1** 起的新號碼（插在陣列中間沒關係，號碼不回收）。
   - ⚠ **增刪節點前先確認該對話在 Unity 已有印記**：`匯出`不會蓋印記，剛匯出回來的檔仍是「舊資料」，第一次同步必須節點數相等、順序不動（工具依順序補印記）。要刪或加節點，先做一次只改欄位的同步讓印記蓋上，再第二次同步增刪（2026-08-26 宗緯家 `#4236` 一役）。
2. **檔案路徑 = Unity 對話名**，不可任意改檔名或搬動檔案（Unity 端以「相對於 `Json/` 的路徑」與 `JsonSource` 印記找對話）。
   - 對話名中的 `/` 是子層（Dialogue System 的子選單），對應 `Json/` 底下的子資料夾：對話 `小溪村後山/赫連娜娜、張寧` ⇄ `Json/小溪村後山/赫連娜娜、張寧.json`。
   - **⚠ 2026-08-26 資料夾重建：根資料夾由 `Json檔/` 改名為 `Json/`，並整份從 Unity 重新匯出**，子層一律以真正的子資料夾呈現。**舊的扁平檔名（把 `/` 寫成 `_`，如 `小溪村_主線起始.json`）自此全部作廢**，對照關係見 `劇情/索引.md`〈舊扁平檔 → 現行對話〉。日後若又看到扁平檔，一律當成漏匯出的殘留，先問作者，不要自行改名或搬動。
   - 新建對話若該放在某子層底下，直接建在對應子資料夾（`Json/<子層>/<對話名>.json`）。
   - Unity 工具視窗最上方要先設定「文案根資料夾」= `Json/`，工具才算得出子層路徑。
3. 引擎指令規則以 `劇情/轉成json指南.md` 為準（擲骰四段包裝、戰鬥四節點、Conditions 不進 Sequence 等）。
4. 翻譯欄位只加值、不動結構：翻譯任務**只**新增/修改 `zh_CN`、`en`（必要時 `zh_TW`），不碰 `text`、`Sequence`、`links`、`entryID`。
5. **`zh_CN` 一律要有，`text` 一改就重翻（已定，2026-08-25 拍板；2026-08-26 作者拍板補強）**

   - **⚠ 有 `text` 就要有 `zh_CN`——這一條沒有豁免（已定，2026-08-26 拍板）。** 節點原本沒有 `zh_CN`，那就是**缺口**，不是「原狀」：回讀、改字、翻譯，任何一種任務碰到都要當場補齊，**不必問作者**。下一項的「原本沒有的欄位不必新增」**只適用 `zh_TW` 與 `en`，對 `zh_CN` 不成立**。整份 JSON 一句未譯也一樣要補到齊（前車之鑑：`大地圖/水濂洞.json` 254 句、`大地圖/天下第一武道大會.json` 409 句、`大地圖/翠影潭.json` 108 句，都曾被「原本沒有就不必補」放過一輪）。
   - **`text` 一經改動，同節點的 `zh_CN` 一律重翻**，不留舊譯；`zh_TW` 鏡像跟著改。此事不必再問作者——有改就翻。節點原本有 `en` 的同理重翻；**`zh_TW`／`en` 原本沒有的欄位不必新增**。
   - **⚠ `zh_TW` 缺不算缺口，不必補（已定，2026-08-26 拍板）**：驗收標準是**「有簡中即可」**——`zh_CN` 要齊，`zh_TW` 有多少算多少。`zh_TW` 只是 `text` 的繁中鏡像，補它沒有實質產出。**回讀時不要為了「補齊 zh_TW」去新增欄位，也不要把它列為待辦。** 已有 `zh_TW` 的節點仍受本鐵則約束：`text` 一改，該欄跟著改。
   - **簡中怎麼寫（依專案既有體例，2026-08-26 從 4 570 句既有對照歸納）**：
     - **只做繁→簡字轉換，不做用詞在地化。** 「這地兒」「哩」「耶」「表哥」「大俠」照留，不改成大陸慣用語。
     - **標點與引擎標記原樣不動**：對話引號維持 `「」`／`『』`（**不換成 `“”`**），全形標點、`[panel=N]`、`[em2]…[/em2]`、`[em7]…[/em7]`、`＊…＊` 一字不改。
     - 幾個常錯的字：`妳`→`你`（簡中無此字；語料裡保留「妳」的舊譯多半是**沒轉乾淨**的，別跟）、`著`→`着`、`牠`→`它`、`乾`→`干`、`裡`→`里`、`鍊`→`链`。
     - **單刪節號 `…` 是本專案的既有體例**（全案 681 處），不要當成錯誤改成 `……`。
   - **空 `text` 的功能節點（擲骰、緩衝、戰鬥觸發、轉場）不需要翻譯欄位**，不算缺口。
6. **要增刪節點前，先確認該對話已經有 `JsonEntryID` 印記（已定，2026-08-26 拍板）**：對話一旦蓋過印記，往後怎麼增刪節點都靠印記精準對應，絕不錯位。**還沒有印記的舊對話（從前用 DialogueGenerator 建的），只有「節點數與 JSON 完全相等」的那一次能自動補印**——先加了節點就把這唯一機會弄掉，工具會跳「無法安全對應」擋下。
   - 正確順序：**先原樣同步一次補印記 → 再改 JSON → 再同步**。
   - 已經加了才發現被擋：把 JSON 還原成與 Unity 相同的節點數 → 同步補印記 → 把改動加回去 → 再同步。（`古墓演出劇情.json` 2026-08-26 即照此救回。）
   - **不要**改用「匯出」重建基準檔來解這種狀況：匯出沒有印記的對話時，`entryID` 會寫成 Unity 的 `entry.id`（不是原 JSON 的號），全檔重新編號，總覽稿的錨點會整份作廢。匯出只在「順序真的錯位、無法依序對應」時才用。
   - repo 裡沒有記錄哪些對話已蓋印記。**動舊檔的節點數之前先問作者「這個對話同步過了嗎」**，不要自己賭。
7. **匯出會覆蓋本機 JSON——匯出之前，先確認手上的修正都已經同步進 Unity（已定，2026-08-26）。**「匯出」是把 Unity 現況倒回檔案，**沒同步過的修正會被整批洗掉**，而且如果那版沒提交進 git 就再也找不回來。
   - 前車之鑑：`大地圖的小溪村.json` 2026-08-26 的兩批修正（22 節點×3 語系的隨手校對＋作者裁定的 9 項）只改了 JSON、沒同步，當天重新匯出後全數失效，且修正版從未提交；能救回來只因為 `劇情/大地圖的小溪村/大地圖的小溪村.md` 把改後的字逐句記著。同批還有 `role 119` → `role119` 的 actorID 修正一併回退。
   - 兩條防線：**(一) 改完 JSON 當天就請作者同步；(二) 同步前先 commit。** 兩件事都沒做的修正，等於還沒發生。
   - 匯出回來之後，**依 `劇情/索引.md` 逐份比對總覽稿**（節點數、entryID、逐句文字），有差異先寫進總覽稿的 ⚠ 區塊，不要默默覆蓋。

## JSON 節點綱要

必填：`entryID`、`actorID`、`text`、`Sequence`（可為 `""`）、`links`。
選填（沒有就整個欄位不寫）：`Conditions`、`Script`、`Description`、`zh_TW`、`zh_CN`、`en`。

```json
{
  "entryID": 12,
  "actorID": "MC8",
  "text": "「三……三百錢？！」",
  "Sequence": "SetPortrait(MC8,pic=4);",
  "Conditions": "IsPassDice() == false;",
  "zh_CN": "「三……三百钱？！」",
  "en": "\"Th-three hundred coins?!\"",
  "links": [13]
}
```

- **`Conditions` 與 `Script` 結尾一律加分號 `;`**（已定，2026-08-27 作者拍板）：`"IsPassDice() == false;"` ✅；`Script` 多行時最後一行也要。Unity 套件會替最後一個指令自動補分號，少寫不會壞，但全案體例統一寫上。
- `Conditions`／`Script` 是 **Lua**：「不等於」寫 **`~=`**（`!=` 是錯的，引擎讀不到，該分支永遠不成立），連接詞用 `and`／`or`／`not`。
- **多條件串接第二段起一律加小括號**：`A == x and (B == y)` ✅／`A == x and B == y` ❌；字串常量一定帶引號：`== "success"` ✅／`== success` ❌。這兩種寫錯都不會報錯，只是該分支永遠走不到。詳見 `劇情/轉成json指南.md` §2 `Conditions` 欄位。
- `zh_TW` / `zh_CN` / `en` 匯入時寫進 Dialogue System 的 `zh-TW` / `zh-CN` / `en` 多語欄位；JSON 沒帶這些欄位時，Unity 既有翻譯**不會**被清掉。
- Unity 端會在每個節點蓋 `JsonEntryID` 印記、對話上蓋 `JsonSource` 印記，之後同步都靠印記精準對應，與節點順序無關。

## 任務一：文案修正（文風修正、追蹤文件、逐句訂正）

作者指令範例：「照 `劇情/舊創作稿/文風修正對照_初出茅廬.md` 把修正套進 Unity」。

1. 讀追蹤文件，逐條取得「舊句 → 新句」。
2. 在 `Json/` 對應檔案中**用語意判斷定位舊句**（JSON 內文字可能與 .md 行號版本略有出入——引號層級、`[panel]`、`[em2]` 標籤等，以 JSON 現況為準；不確定的條目列出來問作者，不要硬套）。
3. 只改 `text`（或追蹤文件明說的欄位），保留節點原有的標籤格式（`[panel=6]＊…＊`、`[em2]…[/em2]` 等）。
4. 修正若涉及多個 JSON 檔，逐檔改完；作者在 IDE 核准 diff。
5. 請作者在 Unity 開「JSON 匯入匯出」→ 選檔或整個資料夾同步 → 確認摘要。
6. 追蹤文件處理完後，依專案慣例在該文件標註已套用狀態。

若懷疑 Unity 內容已和 `Json/` 脫節（曾在 Unity 手改過）：先請作者「匯出」該對話，以匯出檔為底合併修正，再走同步。

### 任務一之附件：文案總覽稿（`劇情/<分組>.md`）

JSON 難讀，作者通讀、校對文風時看的是 AI 從 JSON **手工回讀**成的總覽稿。它是**產物**，地位與 `Json/` 相反——不是事實來源，也不是創作稿；直接改它不會進遊戲。

**為什麼是手工不是腳本（已定）：** 回讀的同時做文風校對（依 `給AI看的指南/武俠文風審校清單.md` 逐句過）。但回讀本身＝**照抄**，不得改字、不得潤飾；校對發現的問題（文風病句、指令錯字、選項順序不一致、標點混用）寫進該章節末尾「回讀時發現的疑點」，要改仍走 JSON。

**做這件事要讀的檔（依序）：** 本節 → `劇情/索引.md`（歸組與進度）→ 範本 `劇情/小溪村/` → `給AI看的指南/立繪指令轉換規則.md` §2（actorID → 人名）→ `給AI看的指南/武俠文風審校清單.md`（校對）。

**分組與命名（已定）**

| 類型 | 檔名 | 收什麼 |
| :--- | :--- | :--- |
| 箱庭 | `劇情/<箱庭名>/`（**一律資料夾**，如 `劇情/小溪村/`） | **2026-08-28 起改資料夾制，14 個箱庭全數完成**：一個箱庭一個資料夾。<br>**① 多 JSON 的箱庭**——一份 JSON 一個 .md，檔名為兩位數序號＋JSON 名（序號＝舊單檔的 §N，所以既有「§4-5」這類指路仍讀得通）；`00 總覽.md` 收檔頭、收錄 JSON 表、說話者對照、分章索引與檔末共通段（修正紀錄等）。<br>**② 單 JSON 的箱庭**——資料夾內就一份 .md，**維持原檔名、不編號**，也不另立 `00 總覽.md`（該檔自己就有檔頭與收錄表）。<br>**③ `Json/` 有子資料夾的照抄**（例：`劇情/英豪府/` 底下再分 `英豪府遴選/`、`英豪府遴選(後)/`，與 `Json/` 同名）。<br>**④ `Json/大地圖/` 那一層不做**，箱庭一律平放在 `劇情/` 第一層（作者 2026-08-28 裁示）。<br>**⑤ 該箱庭的設定檔／結局檔一併收進來**，冠 `@` 前綴以示位階（`@設定_*.md`、`@結局_*.md`）。 |
| 養成模式（主線＋支線） | `劇情/<年>年事件/`（資料夾，如 `劇情/179年事件/`） | **2026-08-28 起改資料夾制**：**一個月一個檔，主線與支線同月合在一起**（主線＝主動觸發，支線＝選「探險」指令後才觸發）。<br>檔名格式 `<兩位數>月(主)<事件簡稱>(支)<事件簡稱>.md`——月份補零好排序，`(主)`／`(支)` 標出哪條線，簡稱列出該月有哪幾件事，**目的是從檔名就找得到戲**。某月只有一條線就只寫那一段。<br>**一個月檔對應兩份 JSON**（`主線事件/<年>年/<月>.json`＋`探索事件/<年>年/<月>.json`），檔內以 `## 主線｜N.` 與 `## 支線｜N.` 分節，N 沿用舊單檔的 §N。<br>`00 總覽.md` 收分月表、兩份舊檔頭、年表與說話者對照。 |

| 角色 | `劇情/<角色名>.md`（如 `赫連娜娜.md`） | 該角色的專屬劇情 JSON |

- **已定（2026-08-25）：主線／支線總覽稿一律「一年一檔」**，檔名 `<年>年 主線事件.md`／`<年>年 支線事件.md`（取代早期規劃的單一 `主線任務.md` 與依地點分的 `支線任務-<地點>.md`）。
- **`劇情/索引.md` 是 JSON → 所在 .md 的唯一對照表。** 新增 JSON 先登記索引，再回讀；歸組拿不準的標「？」問作者，不自行猜。
- 同一 JSON 可同時出現在箱庭／主線／支線檔與角色檔（例：`小溪村後山/赫連娜娜、張寧.json` 同時在 `劇情/小溪村後山/`、`赫連娜娜.md`、`張寧.md`）。
- **同步連動鐵則：** JSON 改動後，索引列出的**每一份** .md 都要重新回讀該章節，不可只更新一份。各檔收錄表的「回讀日期」不一致＝已脫節。
- **⚠ 總覽稿與創作稿撞名的處理（已定，2026-08-26 拍板「解法一」）：** 要建的總覽稿檔名，`劇情/` 底下常常**已經有一份同名的創作稿**（手寫劇本），直接建會把它蓋掉（2026-08-25 `劇情/大地圖的小溪村/大地圖的小溪村.md` 已發生過一次，靠 git 還原）。標準程序：
  1. **先回讀**——總覽稿暫時不要用那個名字，也**不要**先動創作稿。
  2. **回讀完成後**，把創作稿 `git mv` 進 `劇情/舊創作稿/`，並在 `劇情/舊創作稿/README.md` 補一列（原本寫什麼／現在看哪裡／轉檔時捨棄的枝節）。
  3. **總覽稿才用乾淨的同名**建在 `劇情/` 底下，同步更新 `劇情/索引.md` 的三張表（總覽稿一覽、JSON → 總覽稿、舊創作稿歸檔）。
  - **創作稿一律不刪**——它是設定檔與指南的出處，也常留著轉檔時捨棄的枝節。
  - 總覽稿檔名**以 JSON／對話名（箱庭名）為準**，不沿用創作稿的標題。例：`大地圖/水濂洞.json` → `劇情/水濂洞/水濂洞.md`（創作稿叫 `水濂洞的眼淚.md`）；`英豪府遴選/` → `劇情/英豪府/`（創作稿叫 `英豪府遴選.md`）。這種情況本來就不撞名，創作稿仍照第 2 步歸檔。
  - 已照此辦理：`宗緯家`、`大地圖的小溪村`（2026-08-26）。待辦清單見 `劇情/舊創作稿/README.md`〈三、待歸檔〉。

**檔內結構**（範本：`劇情/小溪村/`——下列第 1–3 項在 `00 總覽.md`，第 4 項起每份 JSON 各自一個 `NN xxx.md`；未改制的單檔箱庭則全部在同一份 .md 裡）

1. 檔頭聲明：由 JSON 回讀、不是創作稿、改字走錨點。
2. 「收錄 JSON」表：JSON 檔名（不可改名）、節點數、zh_CN 有無、回讀日期、亦收錄於哪些檔。
3. 「說話者對照」表：本檔用到的 actorID → 寫作名稱 → 依據。
4. （箱庭檔可有）事件大綱、登場人物、主要地點——從舊創作稿搬來，供讀劇情。
5. 每個 JSON 一個 `## N. <JSON 檔名>` 章節，章節開頭 blockquote 寫：對應 JSON 路徑、節點數（有文案數）、entryID 範圍、zh_CN、回讀日期、一句內容摘要。
6. 章節末尾：「孤兒節點」（無任何連入的節點，照抄保留）、「回讀時發現的疑點」（指令錯字、順序不一致、標點混用等，只記錄不改）。

**行格式**

```markdown
**說話者:**`#entryID`　文案（[panel=N]、[em2]…[/em2]、＊…＊ 等引擎標記原樣照抄）
- Sequence: `…`
- Conditions: `…`
- Script: `…`
- 註記：<Description 原文>
```

- 說話者：`actorID` 依 `給AI看的指南/立繪指令轉換規則.md` §2 換成人名；主角寫「燕不凡」；`role2`／`2` 是旁白；`0`／`MC0` 是系統節點不標說話者。查不到的 `roleNNN` 必須先在該檔「說話者對照」表列出推定人名與依據（文案中被叫出的名字、舊創作稿的稱呼）才可用人名，否則原樣寫 `roleNNN`，**不得自行取名**。
- 只呈現 `text`；`zh_TW`／`zh_CN`／`en` 不貼（翻譯在 JSON）。
- 欄位為空就不寫那一行。Sequence 原檔多行者合併成一行，`;` 後補一個空格，其餘一字不改。
- 空文案功能節點用 blockquote：`> ⚙ `#N` <用途一句話>`；擲骰節點 `> 🎲 `#N` <檢定名>（難度 N）`；其下用 `> - Sequence: …` 列指令。
- 分支：走訪順序**深度優先**，多個 links 依 JSON 順序。玩家選項用編號清單，前置一行 `**◆ 玩家選擇**`，每個選項標「→ **分支 X**」；條件分支（Conditions 分流）前置一行 `**▶ 分支名**`，巢狀用 `**▶▶**`；分流節點加一行 `- 分流：成功 → `#a`；失敗 → `#b``；走到已出現過的節點只寫「→ 接 `#N`」不重貼；合流處一行 `**◆ 合流**`。
- 不縮排（Markdown 縮排四格會變程式碼區塊）。

**改字流程（不要直接編輯總覽稿）**

作者指名錨點（「`小溪村/主線起始.json` #77 這句改成…」）→ AI 改 JSON（`text` ＋ `zh_TW` 鏡像 ＋ **重翻 `zh_CN`**，見鐵則 5）→ 作者核准 → Unity 同步 → 依 `索引.md` 重新回讀所有含該 JSON 的總覽稿章節，更新回讀日期。

文風修正（整批套用審校清單）走同一條路。依 `給AI看的指南/武俠文風審校清單.md` 的分類决定要不要先問：**錯字、簡體字、半形標點、漏字病句**是客觀錯誤，直接改；**禁詞替換**照清單自己的「替換」欄改；**網路流行語與現代梗**依清單總則「一律列出，由作者定奪」，只列不改。

## 任務二：新劇本進 Unity（跳過手動轉檔）

作者指令範例：「把 `劇情/雙世冥劍.md` 進 Unity」。

1. AI 依 `劇情/轉成json指南.md` 將 .md 轉成 JSON，存到 `Json/<對話名>.json`（相對路徑即未來的 Unity 對話名；要放進子層就用子資料夾，例如 `Json/小溪村後山/某對話.json` → 對話名 `小溪村後山/某對話`）。
2. 作者在 IDE 核准 diff。
3. 作者在 Unity 同步該檔：資料庫沒有這個對話 → 工具自動**建立新對話**（含 START、連線、印記），不再需要手動跑 DialogueGenerator。

## 任務三：翻譯

作者指令範例：「把 `Json/觀心.json` 翻成簡中／英文」。

1. 在原檔每個有 `text` 的節點加 `zh_CN` / `en` 欄位（遵守鐵則 4：不動其他任何東西）。
2. 空 `text` 的功能節點（擲骰、緩衝、戰鬥觸發）不需要翻譯欄位。
3. 引擎標記原樣保留不翻（`[panel=N]`、`[em2]…[/em2]`、`＊…＊` 的星號結構）；文風遵守 `給AI看的指南/武俠文風創作指南.md` 的精神，英文另循作者指示。
4. 作者核准 → Unity 同步，翻譯進多語欄位。之後修訂翻譯＝改同一批欄位再同步。

## Unity 端行為備忘（工具做什麼、不做什麼）

- 同步＝以 JSON 為準：更新欄位、新增節點、移除 JSON 已刪的節點、重建連線；**跨對話的連線與無印記的手動節點不會被動到**。
- 套用前跳摘要確認（更新／新增／移除數量），套用後可 Ctrl+Z，Console 有逐筆紀錄。
- 舊對話（沒有印記、從前用 DialogueGenerator 建的）第一次同步：節點數與 JSON 一致→自動依順序補印記；不一致→工具會擋下。**匯出本身不蓋印記**，被擋下時「再匯出一次」沒有用——正確做法是先把 JSON 節點數對回 Unity 的數量（暫時放回被刪的節點）同步一次補印記，再刪一次同步。
- 「文案根資料夾」設錯（或沒設）時，工具只拿檔名猜對話，舊扁平檔與子資料夾檔會猜到**同一個對話**；此時絕不要按「同步整個根資料夾」。
- 相容舊格式文案：`BeginDiceRoll` 未帶四段包裝會自動補（已帶則不重複）；`pic=表情名稱` 自動轉數字 ID。
- 匯出：對話名含 `/` 會寫進對應子資料夾；同資料夾若還留著舊扁平檔，完成視窗會列出來，請手動刪除舊檔（不然兩份會重複）。「匯出全部」任何一段失敗都會列在完成視窗，不會整批中斷。
