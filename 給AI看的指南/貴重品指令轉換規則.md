# 貴重品指令轉換規則

本文件說明如何在劇情 Markdown／JSON 中給予玩家物品。轉 JSON 見 `劇情/轉成json指南.md` §3.6。

## 目前沒有一般道具

劇情裡給玩家的東西**一律是貴重品**。沒有「一般道具／背包道具」這套系統，**不要**寫 `Inventory` 或 `AddItem`。

## 正確指令

```
ModifyData(Valuable,Player,DragonHorn,1);
```

-   `Valuable`：資料類別（貴重品）。
-   `Player`：主角（CSV 範例有時寫 `MC1`，劇本慣例用 `Player`）。
-   `DragonHorn`：貴重品 ID。**依該件實際 ID 替換**，必須是英文 ID，不可寫中文名。
-   `1`：數量（或該貴重品系統要求的數值）。

可與立繪／表情寫在同一條 Sequence：

```
**旁白:**：[panel=6]＊（…… **【獲得貴重品：蛟龍角】**）＊
**Sequence DisableCharacterExpression(3);ModifyData(Valuable,Player,DragonHorn,1);**
```

## 禁止的舊寫法

| 錯誤 | 正確 |
| :--- | :--- |
| `ModifyData(Inventory,AddItem,DragonHorn,1);` | `ModifyData(Valuable,Player,DragonHorn,1);` |
| `ModifyData(Inventory,AddItem,RiverGodsTear,1);` | `ModifyData(Valuable,Player,Rivertear,1);` |
| `AddItem(FanZhenCao,1);` | `ModifyData(Valuable,Player,FanZhenCao,1);` |

CSV「特殊標籤」亦以 `ModifyData(Valuable,...)` 開頭，但**沒有數量參數**（例如 `ModifyData(Valuable,MC1,SwordProficiency);`），那是標籤不是物品，不要拿來發蛟龍角。

## 開啟貴重品便籤 `ShowValuableMemo(ValuablesID);`

在對話中把該件貴重品的**便籤（備忘錄）**叫出來給玩家看。**與獲得指令 `ModifyData(Valuable,...)` 分開寫。**

```
ShowValuableMemo(Oddlist);
```

-   `ValuablesID`：同一組英文 ID，與發放、`IsValuablesObtained` 用的完全一致，**不可寫中文名**。
-   **用途：** 長篇文字（名冊、紙條、手記、卷）**不寫進對話節點**，放在貴重品資料裡，由這道指令呼叫。對話那一格只留一句「……」或空白，內容交給便籤演。

### ⚠ 鐵則一：一定排在「已經拿到」之後

**便籤讀的是玩家手上那件東西**，沒持有就開不出來。所以 `ShowValuableMemo` 必須排在 `ModifyData(Valuable,Player,<ID>,1);` **之後**——不論是同一段 Sequence 的下一行，還是下一個節點。

> **定樁事故：** `Json/破廟/阿傑、阿佑、阿偉、水井.json` `#3274` 原本自己給一次名冊、又在同段 Sequence 把 memo 排在 `ModifyData` 前面，等於既重複發物、又依賴尚未持有的東西。2026-08-26 作者裁定：**`#3272` 負責給、`#3274` 只負責開。** 見 `劇情/破廟/00 總覽.md`。

### 兩種現行寫法（都在遊戲裡）

**甲、獨立空節點＋攔住推進（要玩家讀完才走）**

```
**旁白:**：[panel=6]＊（…… **【獲得貴重品：教眾名冊】**）＊
**Sequence ModifyData(Valuable,Player,Oddlist,1);**

**Sequence SetContinueMode(false);SetContinueMode(original)@Message(EndMemo);Continue()@Message(EndMemo);ShowValuableMemo(Oddlist);**
```

（`Json/破廟/阿傑、阿佑、阿偉、水井.json` `#3272`→`#3274`）

-   `SetContinueMode(false);` 先關掉點擊推進。
-   `@Message(EndMemo)` ＝**等便籤關閉才觸發**：關閉的當下恢復推進模式，並自動 `Continue()`。
-   效果：**便籤沒關掉，對話就停在那裡。** 這是「非讀不可」的正規寫法。該節點 `text` 留空。

**乙、掛在一句台詞上（讀不讀隨玩家）**

```
**你:** 「……」
**Sequence DisableCharacterExpression(0);ShowValuableMemo(FollowersLeftNote);**
```

（`Json/趙王洞/山賊窩.json` `#4146`）

-   台詞只留 `「……」`——主角沒話說，內容全在便籤裡。
-   沒有攔截，玩家關掉便籤後照常點擊推進。

**怎麼挑：** 那段文字**是不是後續劇情的前提**？是（名冊、線索、任務憑據）→ 用甲；只是氣氛與補充 → 用乙。

## 讀取持有狀態（寫在 `Conditions`，不寫進 `Sequence`）

```
IsValuablesObtained("Player", "Rivertear") == true;
```

-   ID 與發放指令用同一組英文 ID（`Rivertear`、`FadedTearstone`…），**不可寫中文名**。
-   **⚠ 和別的條件串接時，第二段起一律用小括號包住整段**（全案體例，見 `劇情/轉成json指南.md` §2）：
    -   ✅ `CurrentQuestEntryState("CF40", 6) == "success" and (IsValuablesObtained("Player", "FadedTearstone") == true);`
    -   ❌ `CurrentQuestEntryState("CF40", 6) == "success" and IsValuablesObtained("Player", "FadedTearstone") == true`
    -   少了括號引擎判不出來，**該分支永遠不成立、也不會報錯**——玩家明明帶著東西卻看不到那個選項。2026-08-27 作者在 `大地圖/水濂洞.json` `#4276` 抓到一筆，同檔另有 `#4275`／`#4283`／`#4284` 三筆同錯，已一併改正。
